# OUTVIDEO-PIPELINE 项目方案 v2

> **定位：你给一段故事脚本，本地 Agent 工作流自动完成后期全部工作，产出成片。**
> 自动化优先，人工只在 2 个低成本闸门介入（编排表、样片）。
> 每阶段输入输出 = 固定 JSON 契约 + 校验器，失败可断点续跑，单镜头可重做。
> 状态：**待审阅**（确认后立即开工 M1）

---

## 0. 主线一句话

```
story.md ──> [S1 结构化] ──> script.json
script.json ──> [S2 index-tts配音+对齐] ──> vo.wav + timing.json   ← 时间真相源
timing.json ──> [S3 视觉编排] ──> storyboard.json ★闸门1(你审5分钟)
storyboard.json ──> [S4 素产] ──> assets/ (ComfyUI本地生图 + 程序化B-roll)
storyboard.json + assets ──> [S5 Remotion装配渲染] ──> 样片60s ★闸门2 ──> 全片
全片 ──> [S6 音轨+QA+交付] ──> final.mp4 + 封面 + QA报告
```

**S5 是心脏**（§3 详解）：所有镜头都是「数据驱动的 Remotion 组件」，镜头怎么动由配方卡决定，什么时候动由 timing.json 决定，长什么样由素材和设计 token 决定——三者分离，改任何一个不牵动其他，这就是输出稳定的结构性保证。

## 2. 六阶段流水线（输入→输出→质检→自动化程度）

### S1 脚本结构化（agent，全自动）
| | |
|---|---|
| 输入 | `story.md` |
| 处理 | 叙事分析：hook/章节/收尾标注 → 语义段拆分（每段 5–15 字短语对齐预期）→ 每段挂「画面潜力标记」（场景可画/信息可图形化/金句/需真实素材） |
| 输出 | `script.json`（分句结构 + 画面潜力标记） |
| 质检 | 校验器：段完整性、无重复、字数分布 |

### S2 配音 + 声学对齐（脚本，全自动）
| | |
|---|---|
| 输入 | `script.json` |
| 处理 | ① **index-tts 本地合成**（整段、单音色、禁止分句拼接——适配器封装，未来换 TTS 只换适配器）② **字级对齐**（复用 video-talkcraft `timestamps_cpu.py`：FireRedASR2 本地，中位 20–40ms，whisper 兜底）③ 三项一致性自检（总时长/段数/末段对齐） |
| 输出 | `audio/vo.wav` + `timing.json`（★真相源：全片时间从此文件读取，schema 禁改） |
| 质检 | fail-fast：末段结束 ≠ 音频时长即自动重对齐一次，再失败即停 |

### S3 视觉编排（agent 生成 + ★闸门1 你审）
| | |
|---|---|
| 输入 | `script.json` + `timing.json` |
| 处理 | 导演视角逐段拆镜：A-roll（IP 小剧场）/ B-roll（信息图形）分类 → 每镜头**强制绑定一张配方卡**（本地模板库或 shotcraft152/talkcraft78 卡库，按语义结构匹配）→ 内部动效节拍锚到具体字 → 转场设计 → 节奏自检（连续同类型≤3、A/B 配比） |
| 输出 | `storyboard.json` + 渲染成 Markdown 七列编排表（文章同款格式，你一屏审完） |
| 你审 | 改口径反馈即可，agent 改 JSON 后重新出表；确认后 S3 锁定 |

### S4 素材生产（脚本 + agent，全自动，contact sheet 快审可选）
| 镜头类型 | 生产方式 | 用到的 skill |
|---|---|---|
| A-roll 场景帧 | **本地 ComfyUI**（127.0.0.1:8188，已验证可跑）：三参考图锁定（三视图+笔触+场景）→ 生成静帧；PuLID/参考图控一致性 | ComfyUI 本体（已装 PuLID-Flux / qwenmultiangle / AnythingXL） |
| A-roll 动态 | **不做图生视频**——静帧分层 + Remotion 运镜/七层动效（§3.3），零 API、零漂移 | talkcraft 七层系统 + shotcraft 运镜卡 |
| B-roll 图形 | **程序化渲染，无需生图**：Remotion 组件 + 设计 token 直接渲 | 内置镜头组件库（§3.2） |
| B-roll 隐喻拼贴 | 可选风格通道：拼贴隐喻动画 | gbro-collage-broll |
| 插画镜头 | 可选风格通道：手绘解释图 | hand-drawn-styles(19配方) / story-to-handdrawn(20风格) / ian-xiaohei |
| 真实素材 | 录屏/截图通道（你提供或 playwright 自动录） | claude-code-video-toolkit 的 playwright-recording |
| 输出 | `assets/` + `assets/manifest.json`（每素材：shot_id/文件/生成参数哈希/QA状态） | |

### S5 Remotion 装配渲染（§3 详解，核心）
| | |
|---|---|
| 输入 | `storyboard.json` + `timing.json` + `assets/manifest.json` + `project.json` |
| 处理 | storyboard → 组件实例树 → **逐镜头分段渲染** → ffmpeg concat → 样片（前60s）先行 |
| 输出 | `render/segments/S*.mp4` → 样片 → 全片视频轨 |
| 你审 | ★闸门2：60s 样片看 A/B 节奏与风格，OK 后全片；单镜头不满意 `redo --shot S007` 只重做该镜头 |

### S6 音轨 + QA + 交付（脚本，全自动）
| | |
|---|---|
| 处理 | BGM 自动闪避（VO 下 -14dB）+ 音效按 cue 落点（预算≤8个/分钟）→ **三重 QA**（静止帧检测/音效能量验证/锚点帧+三连帧抽检 + 音画偏差>80ms 报警）→ 响度归一 → 母版+分享双码率 → 九帧 contact sheet → 封面生成 |
| 输出 | `out/final.mp4` + `out/cover.png` + `qa/report.json` |

## 3. 核心引擎：Remotion 装配架构（S5 详解）

### 3.1 工程结构（新建 `render-engine/`）

```
render-engine/src/
  compositions/
    VideoRoot.tsx                  # 读 storyboard.json 生成整片 Sequence 树（预览用）
    ShotComposition.tsx            # 单镜头 Composition（分段渲染入口）
  shots/                           # ★镜头组件库 = B-roll 模板库（稳定输出的物质基础）
    a-roll/ARollScene.tsx          # A-roll：分层静帧(角色/前景/背景) + 运镜
    b-roll/CompareCard.tsx         # 方案对比卡
    b-roll/FlowSteps.tsx           # 流程步骤卡
    b-roll/ListGrid.tsx            # 横向排列/清单卡
    b-roll/Aggregation.tsx         # 聚合/收敛
    b-roll/Hierarchy.tsx           # 层级/组成
    b-roll/QuoteCard.tsx           # 金句/章节卡
    b-roll/FilterFunnel.tsx        # 筛选/漏斗
  systems/                         # ★全局动效系统（一次实现，所有镜头复用）
    CameraRig.tsx                  # 连续相机曲线 + 重音冲击脉冲（talkcraft G1）
    Parallax.tsx                   # 深度视差层 0.6/1.0/1.3（G2）
    IdleRetire.tsx                 # 元素呼吸 + 让位生命周期（G3）
    Environment.tsx                # 呼吸 vignette + 扫光 + 分幕色温（G4）
    Transitions.tsx                # 六式运动承接转场（G5）
  captions/
    KaraokeLine.tsx                # 素排字幕：整句硬现硬走，字级时间驱动（talkcraft 铁律）
  lib/
    loader.ts                      # storyboard/timing/assets → 组件 props（纯函数）
    tokens.ts                      # 设计 token（project.json → 颜色/字体/间距）
```

### 3.2 镜头组件的固定接口（数据结构落到渲染层）

```ts
interface ShotProps {
  shot: Shot;         // storyboard.json 的一个镜头对象（schema 见 §6）
  timing: Segment[];  // 该镜头覆盖的时间轴短语段（含字级锚点）
  assets: AssetMap;   // shot_id → 素材文件路径
  tokens: StyleTokens;// 全局设计 token
}
```

**任何新镜头 = 新组件 + 注册到 `shots/index.ts`**，storyboard.json 的 `recipe_ref` 按组件名引用。组件内部禁止硬编码时间/颜色/文案——全部来自 props。这保证：同一模板在不同视频里产出风格一致，模板升级全库受益。

### 3.3 A-roll 动态的实现（无图生视频 API）

静帧进 Remotion 后不是"一张死图"：
1. **分层**：生图时前景/角色/背景分层出图（或单图 + 前景 mask），各挂不同 depth
2. **运镜**：CameraRig 连续曲线（慢推/横移/微旋）+ 重音帧冲击脉冲（对应旁白重音字）
3. **视差**：深度系数驱动各层位移差 → 2.5D 空间感
4. **呼吸**：IdleRetire 让角色/元素持续微动（scale ±0.5% sin 呼吸），静止帧结构性不可能出现
5. **生命周期**：主体让位规则——新元素入场时旧主体缩小退后，画面不堆积

这套全部来自 talkcraft 已验证的系统，我们只做参数化封装。

### 3.4 渲染策略：分段 + 拼接（幂等的关键）

```
storyboard.json 的每个 shot
  → ShotComposition（固定 fps/画幅，时长 = end_ms - start_ms）
  → npx remotion render（并发 2，MPS/CPU）
  → render/segments/S007.mp4
全镜头完成 → ffmpeg concat（转场在镜头组件首尾自实现，免跨段 xfade）
→ 样片 = 前 60s 涉及的 segments 先拼 → 你审 → 全片拼
```

单镜头失败/不满意 → 只重渲该段，其余不动。**渲染成本与修改范围成正比，不与片长成正比。**

## 6. 数据契约汇总（5 个 JSON + 1 个状态文件）

| 文件 | 生成者 | 可否人工改 | 核心字段 |
|---|---|---|---|
| `project.json` | S0 | ✅ 可改 | 画幅/fps/设计token/IP参考图路径/音色/BGM偏好 |
| `script.json` | S1 | 闸门1前可改 | segments[]（text/hook标记/画面潜力标记） |
| `timing.json` | S2 机器 | ❌ 禁改 | duration_ms、segments[]（start_ms/end_ms/text/字级chars） |
| `storyboard.json` | S3 | ★闸门1唯一可改对象 | shots[]（id/time/roll/b_type/view_angle/intent/visual/motion[]/transition_in/recipe_ref/assets_needed/status） |
| `assets/manifest.json` | S4 | ❌ | 素材↔shot_id 映射 + 生成参数哈希 + QA 状态 |
| `state.json` | 状态机 | ❌ | 各阶段状态：pending/running/blocked(闸门)/done |

每个 JSON 配 `schema/*.json`，阶段入口先校验后执行。**schema 版本化（pipeline_version），升级不破坏旧 job 续跑。**

## 7. 方差控制六把锁（不变，简要）

① 配方强制（recipe_ref 必填，禁自由发挥）② 一致性参考图锁（三视图+笔触+场景，参数哈希留痕）③ 时间轴真相源禁改 ④ 决策前置+成本闸门（编排表/样片两道，单次审阅≤5分钟）⑤ 自动 QA 三重门 ⑥ 状态机幂等（重跑只做失败镜头）。
